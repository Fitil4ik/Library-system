# Специфікація вимог та Use Cases (Library-system)

## Намір
Описати функціональні та нефункціональні вимоги до системи управління бібліотекою, змоделювати прецеденти (Use Cases) та детальні сценарії поведінки для процесу повернення книги.

## Предметна область (узгоджено з ER-моделлю Лаб 1)
- Актори:
  - Reader (Читач) - людина.
  - PaymentGateway (Платіжний шлюз) - зовнішня система.
  - EmailService (Сервіс розсилок) - зовнішня система.
- Сутності та атрибути:
  - Reader (id: uuid, email: string, full_name: string)
  - Author (id: uuid, full_name: string)
  - Book (id: uuid, title: string, publication_year: number, status: enum [AVAILABLE, LOANED, LOST])
  - Loan (id: uuid, reader_id: uuid, book_id: uuid, borrow_date: date, return_date: date, fine_amount: decimal)

## Бізнес-правила (уточнено перед генерацією)
- Стандартний термін позики: 14 днів від borrow_date (фіксується у return_date).
- Штраф за прострочення: 10.00 грн за кожен день після return_date у поле fine_amount.
- Втрата книги: при повідомленні читача про втрату статус книги змінюється на LOST, нараховується фіксований штраф 500.00 грн у fine_amount, після оплати через PaymentGateway позика закривається.
- Сповіщення EmailService: відправляються при поверненні книги без штрафу, після оплати штрафу (квитанція) та після оплати компенсації за втрату книги.

## Критерії прийняття для AI
1. Use Case діаграма у синтаксисі Mermaid (для вставки в Markdown):
   - Мінімум 2 типи акторів (людина та зовнішні сервіси).
   - Базові прецеденти: Пошук книги (UC_Search) з узагальненням (generalization) на Пошук за назвою (UC_SearchByTitle) та Пошук за автором (UC_SearchByAuthor), Видача книги (UC_Borrow), Повернення книги (UC_Return).
   - Для UC_Return використати зв'язки include (Перевірка статусу позики UC_CheckLoanStatus, Відправка сповіщення UC_SendNotification) та extend (Оплата штрафу UC_PayFine).
2. Функціональні вимоги (FR) у класичному англійському синтаксисі EARS (WHEN / IF / WHILE ... THEN the System SHALL ...).
3. Нефункціональні вимоги (NFR) окремим блоком після FR (не наносяться на Use Case діаграму та не входять до матриці трасування):
   - Час відгуку: не більше 300 мс (для 95% запитів) при обробці повернення та розрахунку штрафу.
   - Пропускна здатність: до 50 одночасних запитів читачів без деградації.
   - Безпека: передача даних до PaymentGateway виключно по TLS 1.3 без зберігання карткових даних у системі.
   - Доступність: 99.5% у робочі години бібліотеки.
   - Локалізація та пристрої: підтримка української та англійської мов, коректна робота у браузерах Chrome, Firefox, Safari з шириною екрана від 360px до 1920px.
4. Сценарії Gherkin (Given/When/Then) для одного складного Use Case (UC_Return - Повернення книги):
   - User story інтегрується безпосередньо в опис фічі/сценарію (окремий розділ User Stories не потрібен).
   - Мінімум 3 сценарії: вчасне повернення, повернення з простроченням та оплатою штрафу, повідомлення про втрату книги з компенсацією.
   - Зовнішні системи (PaymentGateway, EmailService) виступають активними акторами дій.
5. Матриця трасування (Markdown таблиця):
   - Зв'язки багато-до-багатьох (N:M) між FR (EARS), Use Cases та Gherkin-сценаріями.
   - Мінімум 1 непокрита функціональна вимога з поясненням.
